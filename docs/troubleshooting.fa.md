# عیب‌یابی

[English](troubleshooting.md) · [بازگشت به README](../README.fa.md)

اول همیشه روی **هر دو** سرور اطلاعات جمع کنید:

```bash
sudo ./bpt.sh status
sudo ./bpt.sh logs            # با Ctrl+C خارج شوید
sudo ./bpt.sh show            # توکن پنهان است؛ با --reveal روی هر دو طرف مقایسه کنید
```

لاگ سالم سمت خارج شامل `control channel established` و `transport tcp is up` است؛ سمت ایران `control channel successfully established` نشان می‌دهد.

## تانل وصل نمی‌شود

| نشانه | علت محتمل | راه‌حل |
|---|---|---|
| لاگ خارج: `connection refused` / `timeout` | پورت تانل ایران بسته یا اشتباه است | پورت را در ufw **و** فایروال ارائه‌دهنده باز کنید. از سرور خارج: `nc -vz IP_ایران 7001` |
| هیچ‌وقت به «established» نمی‌رسد یا خطای مفیدی نیست | **ناهماهنگی توکن** (طبق مستندات BackPack ممکن است شبیه تانل مرده باشد) | `./bpt.sh show --reveal` را روی دو طرف مقایسه کنید. روی خارج `install --force` را با همان توکن دوباره بزنید |
| دیروز کار می‌کرد، امروز نه | آی‌پی ایران عوض شده یا **مسدود** شده | از خارج `ping IP_ایران` / `nc -vz` بزنید. آی‌پی جدید: روی سرور خارج `./bpt.sh set-server IP_جدید` |
| از خارج `nc` تایم‌اوت می‌شود ولی سرور روشن است | ارائه‌دهنده/ISP ایران آن مسیر یا پورت را فیلتر می‌کند | پورت تانل دیگری امتحان کنید (`443`، `8443`، `2053` …). «فیلتر مسیر» را در ادامه ببینید |
| سمت ایران `address already in use` | برنامه‌ی دیگری از پورت تانل یا پورت فوروارد استفاده می‌کند | `ss -ltnp \| grep :7001`؛ پورت دیگری بگیرید |

## تانل بالاست ولی کاربران وصل نمی‌شوند

1. **پورت فوروارد بسته است:** `ss -ltn | grep ':443 '` روی سرور ایران وقتی تانل بالاست باید یک listener نشان دهد. اگر نشان داد، پورت را در فایروال باز کنید (ufw **و** پنل ارائه‌دهنده)؛ اگر نه، دلیلش را در `./bpt.sh logs` ببینید.
2. **پشت پورت چیزی نیست:** `443` یعنی `127.0.0.1:443` روی سرور خارج. روی سرور خارج `ss -ltn | grep ':2096 '` را بررسی کنید و مطابق آن بنویسید (`443=127.0.0.1:2096`). یادداشت README را ببینید.
3. **سرویس‌های UDP (وایرگارد، Hysteria، DNS، بازی …):** با `--udp yes` (پیش‌فرض) نصب کنید و پورت‌های **UDP** فایروال را هم باز کنید.
4. **سرویس مقصد اتصال را رد می‌کند:** سرویس همه‌ی کاربران را از طرف تانل (`127.0.0.1` / سرور خروجی) می‌بیند. پنل‌هایی که محدودیت به‌ازای هر آی‌پی، بن آی‌پی یا قانون جغرافیایی دارند، ممکن است همه‌ی کاربران را یک کاربر حساب کنند. این محدودیت‌ها را برای مبدأ تانل شل کنید.

## کندی و لگ

به ترتیب بررسی کنید:

1. **fail2ban آی‌پی ایران را بن کرده است** (روی x-ui/3x-ui خیلی رایج است): روی سرور خارج
   `fail2ban-client status` ← `fail2ban-client status <jail>`؛ اگر آی‌پی ایران در فهرست بود، آزادش و سفیدلیستش کنید:
   ```bash
   sudo fail2ban-client set <jail> unbanip IP_ایران
   sudo ./bpt.sh ignore-ip IP_ایران
   ```
2. **الگوریتم کنترل ازدحام:** روی **هر دو** سرور `sudo ./bpt.sh tune` را بزنید (BBR + بافرها).
3. **مسیر خام** بین دو سرور را بیرون از تانل بسنجید:
   `ping -c 20 IP_ایران` (تلفات؟ جیتر؟) و اگر دارید `iperf3`. تلفات و جیتر زیاد مشکل شبکه است، نه تانل.
4. **تعداد اتصال آماده (pool):** برای کاربران هم‌زمان زیاد `--pool` را روی سمت خارج بالا ببرید: `sudo ./bpt.sh install kharej --force --server … --token … --pool 16`.
5. **CPU/RAM:** با `top` ببینید؛ یک VPS خیلی کوچک می‌تواند گلوگاه باشد.
6. **مشکل MTU** (بعضی سایت‌ها هنگ می‌کنند و صفحه‌های بزرگ بالا نمی‌آیند): [`mss-clamp.md`](https://github.com/AminMGMT/BackPack/blob/main/docs/mss-clamp.md) در مستندات BackPack را ببینید.

### فیلتر مسیر

بعضی مسیرها **TCP را در یک جهت** رها می‌کنند یا کند می‌کنند ولی UDP را رد می‌کنند، یا بعد از مدتی پورت/آی‌پی خاصی را فیلتر می‌کنند. نشانه: `ping` سالم است، تانل وصل می‌شود، ولی فقط در یک جهت بسیار کند است.

* تانل معکوس (همین اسکریپت) باعث می‌شود **سرور خارج** اتصال را به ایران باز کند و معمولاً از جهت کندشده فرار می‌کند. اگر باز هم بد بود، پورت تانل یا آی‌پی را عوض کنید یا ترنسپورت دیگری از BackPack را امتحان کنید (`sudo backpack` ← *Link Test* مسیر را می‌سنجد و پیشنهاد می‌دهد).
* اگر آی‌پی ایران مسدود شد، آی‌پی جدید بگیرید و روی سرور خارج `./bpt.sh set-server IP_جدید` بزنید (با دامنه فقط DNS عوض می‌شود).

## مشکل نصب‌کننده

| پیام | معنی / راه‌حل |
|---|---|
| `download failed` | سرور به GitHub دسترسی ندارد. [نصب آفلاین](guide.fa.md#نصب-آفلاین) یا آینه |
| `checksum mismatch - refusing to install` | فایل خراب یا دستکاری شده است. دوباره دانلود کنید؛ اگر ادامه داشت نصب نکنید |
| `unsupported CPU` | برای این پردازنده نسخه‌ی آماده نیست — BackPack را از روی سورس بسازید |
| `run as root` | از `sudo` استفاده کنید |
| `tunnel 'X' not found` | `--name` اشتباه است؛ `./bpt.sh list` |
| خطوط `[dry-run]` چاپ می‌شود | `--dry-run` یا `BPT_ROOT` فعال است؛ آن را بردارید |

## لاگ و ری‌استارت تمیز

```bash
sudo ./bpt.sh restart
journalctl -u backpack-bpt --since "10 min ago" --no-pager
```

## گزارش باگ

یک Issue باز کنید و این‌ها را بنویسید: سیستم‌عامل (`cat /etc/os-release`)، `uname -m`، خروجی `./bpt.sh show` (توکن پنهان) و ۳۰ خط آخر لاگ **هر دو** سرور. هرگز توکن را منتشر نکنید.
